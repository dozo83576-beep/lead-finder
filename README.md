# Lead Finder

Локальный инструмент для поиска компаний, которым может понадобиться новый сайт или техническая доработка существующего.

Инструмент использует данные OpenStreetMap, при наличии ключа ищет официальный домен через Yandex Search API, сохраняет доказательства проверки в SQLite и готовит персональные обращения. Модуль **Lead Outreach** отправляет разрешённые email-цепочки через Unisender, получает ответы по IMAP Яндекс 360 и ведёт входящие Telegram-диалоги после `/start` пользователя. Режим **Привлечение и CRM** учитывает ручной нетворкинг, партнёров, сделки, платежи и комиссии.

## Установка

Требуется установленный Python 3.14.

```powershell
cd D:\Freelance
py -3.14 -m pip install -r requirements.txt
```

## Запуск

```powershell
py -3.14 -m streamlit run app.py
```

В Windows приложение также можно запускать ярлыком **Lead Finder** на рабочем столе. Ярлык **Остановить Lead Finder** завершает фоновый сервер.

Streamlit покажет локальный адрес, обычно `http://localhost:8501`.

Для первой проверки включите **Тестовый запуск без сети** и нажмите **Найти и проверить**. Dry Run показывает три тестовых лида и ничего не записывает в базу.

## Рабочий сценарий

1. Укажите город.
2. Выберите одну из десяти ниш или вариант **Другая ниша**.
3. Для другой ниши обязательно укажите ключевое слово.
4. Проверьте показанный расчёт стоимости и запустите поиск.
5. Сначала работайте с разделом **Готовые лиды**. Записи из раздела **Требуют подтверждения** проверьте вручную.
6. В карточке можно подтвердить отсутствие сайта, указать найденный сайт, проверить актуальность текущего домена или открыть ручной поиск в Яндексе.
7. Сохраните статус и заметку либо скачайте текущую выборку как CSV/XLSX.
8. В разделе **Lead Outreach** зафиксируйте согласие, проверьте черновик, создайте кампанию и сначала выполните Dry Run очереди.
9. Переключитесь в **Привлечение и CRM**, чтобы вести площадки, партнёрские рекомендации, сделки и ручные платежи.

Повторный поиск обновляет автоматические данные, но сохраняет ручной статус и заметку.

## Lead Outreach

Публичный email, найденный на сайте, в OSM или при импорте, получает статус `unknown`. Он доступен для черновика, но не для отправки. Email разрешается добавить в кампанию только после сохранения статуса `consented` с источником, доказательством и датой согласия. Входящий Telegram-диалог получает статус `inbound` автоматически только после перехода пользователя по одноразовой ссылке и команды `/start`.

Система создаёт цепочку из четырёх писем на дни 0, 3, 8 и 13, планирует их на рабочие дни с 10:00 до 12:00 в часовом поясе кампании и немедленно останавливает следующие шаги после ответа, отписки, complaint или hard bounce. Неподтверждённое отсутствие сайта не используется как факт. Open rate не является KPI и tracking pixel отключён.

Реальная отправка заблокирована одновременно на трёх уровнях — UI, worker и адаптер Unisender — пока не выполнены все условия:

- у контакта есть `consented` или `inbound` и нет suppression;
- настроены переменные окружения;
- вручную подтверждены SPF/DKIM/DMARC, отписка и контрольная доставка;
- включён флаг производственной отправки.

Стартовый предел — максимум 5 адресатов в день. Через семь дней без технических ошибок, complaint и hard bounce интерфейс разрешает увеличить его не более чем на 25%. Любая complaint ставит кампанию на паузу. Два hard bounce в кампании до 20 адресатов также ставят её на паузу. Повторный запуск worker и повторная обработка provider event не создают дубликатов.

### Переменные окружения

Создайте брендированный поддомен вида `connect.example.ru`, почтовый ящик Яндекс 360 и подтверждённого отправителя Unisender. Для campaign API Unisender адрес ответа должен совпадать с адресом отправителя, поэтому `OUTREACH_REPLY_TO` и `OUTREACH_FROM_EMAIL` задаются одинаковыми.

```powershell
[Environment]::SetEnvironmentVariable("UNISENDER_API_KEY", "ваш_ключ", "User")
[Environment]::SetEnvironmentVariable("UNISENDER_LIST_ID", "id_списка", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_SENDER_NAME", "Имя Фамилия", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_FROM_EMAIL", "name@connect.example.ru", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_REPLY_TO", "name@connect.example.ru", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_IMAP_HOST", "imap.yandex.ru", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_IMAP_USERNAME", "name@connect.example.ru", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_IMAP_PASSWORD", "пароль_приложения", "User")
[Environment]::SetEnvironmentVariable("TELEGRAM_BOT_TOKEN", "токен_BotFather", "User")
[Environment]::SetEnvironmentVariable("TELEGRAM_BOT_USERNAME", "username_бота", "User")
[Environment]::SetEnvironmentVariable("OUTREACH_LINK_SECRET", "случайная_длинная_строка", "User")
```

Значения читаются только из окружения, не показываются в интерфейсе, не сохраняются в SQLite и не попадают в экспорт. Для IMAP используйте отдельный пароль приложения и включите 2FA в Яндекс 360 и Unisender.

### DNS и контрольный запуск

1. Настройте MX Яндекс 360, одну объединённую SPF-запись, отдельные DKIM Яндекса и Unisender и DMARC с `p=none` и адресом для отчётов.
2. Проверьте на собственных адресах Gmail, Яндекс, Mail.ru и Outlook значения `SPF=pass`, `DKIM=pass`, `DMARC=pass`, TLS, From и отписку. После стабильной работы повышайте DMARC до `quarantine`, затем `reject`.
3. В интерфейсе выполните **Dry-run очереди**. Он не делает внешних запросов и не записывает факт отправки.
4. Выполните seed-тесты из кабинета Unisender на собственные адреса. Только после них отметьте четыре защитные проверки в разделе **Доставляемость**.
5. Запускайте первый пилот максимум на 5 адресатов с доказанным согласием.

Unisender автоматически добавляет строку отписки согласно языку сообщения. В коде используются методы [`subscribe`](https://www.unisender.com/ru/support/api/contacts/subscribe/) с `double_optin=3` только после локальной проверки согласия, [`createEmailMessage`](https://www.unisender.com/ru/support/api/messages/createemailmessage/) и [`createCampaign`](https://www.unisender.com/ru/support/api/messages/createcampaign/). Статусы доставки синхронизируются через общую статистику и асинхронный [delivery report](https://www.unisender.com/ru/support/api/statistics/getcampaigndeliverystats/).

### Worker

Безопасная локальная проверка очереди:

```powershell
py -3.14 outreach_worker.py --dry-run
```

Один рабочий цикл после выполнения защитных проверок:

```powershell
py -3.14 outreach_worker.py
```

Постоянный long polling email/Telegram и обработка очереди:

```powershell
py -3.14 outreach_worker.py --loop --interval 60
```

Worker не стартует автоматически вместе с Streamlit: это исключает случайную отправку после запуска ярлыка. Telegram-бот никогда не пишет по найденным `t.me`-адресам; оператор может отвечать только в уже открытом входящем диалоге.

## Привлечение и CRM

Второй режим Lead Outreach предназначен для одного локального оператора и состоит из четырёх разделов:

- **Площадки** — ручной каталог Telegram, TenChat, VK и других сообществ, оценки активности и соответствия аудитории, профили позиционирования с доказательствами и журнал ручных касаний;
- **Партнёры** — условия работы, рекомендации и снимок комиссии на момент представления лида;
- **Сделки** — единая воронка `new → qualified → discovery → proposal → negotiation → won | lost`, задачи, проверяемые наблюдения, квалификация, возражения и ссылки на документы;
- **Финансы** — ручные клиентские платежи и партнёрские комиссии `accrued | due | paid | cancelled`.

CRM не выполняет сетевых запросов, публикаций, личных сообщений или переводов денег. Рекомендация и ручное добавление лида в CRM не меняют `contact_permissions` и не обходят suppression. Положительный входящий ответ позволяет оператору отдельной кнопкой создать идемпотентную сделку и задачу квалификации.

Стоимость и платежи хранятся целыми копейками, комиссии — basis points. Комиссия фиксируется на рекомендации и становится `due` только после выигрыша, полной оплаты клиентом и окончания срока выплаты партнёру. Перевод подтверждается вручную. Финансовый CSV создаётся только отдельной кнопкой и не содержит контактов или текстов переписки.

TGStat открывается только как ручная ссылка. Автокомментарии, массовые Telegram/TenChat DM, холодные звонки, парсинг 2ГИС и LLM-копирайтинг не реализованы.

## Yandex Search API

Без ключей инструмент работает, но не делает вывод об отсутствии сайта: такие компании остаются в очереди ручной проверки.

Для автоматической проверки задайте две переменные среды и перезапустите приложение:

```powershell
[Environment]::SetEnvironmentVariable("YANDEX_SEARCH_API_KEY", "ваш_ключ", "User")
[Environment]::SetEnvironmentVariable("YANDEX_FOLDER_ID", "идентификатор_каталога", "User")
```

По умолчанию месячный бюджет — 300 ₽, расчётная цена — 488 ₽ за 1000 синхронных запросов. Оба значения настраиваются перед запуском. Актуальную цену проверяйте в [официальном тарифе Yandex Search API](https://aistudio.yandex.ru/docs/ru/search-api/pricing.html).

Кнопка **Проверить подключение к Yandex API** выполняет один реальный тарифицируемый запрос и не показывает ключ. Этот диагностический запрос не добавляется во внутренний месячный счётчик Lead Finder.

Во время поиска инструмент автоматически проверяет только компании без сайта и сломанные сайты, полученные из OpenStreetMap. Перед платным запросом Lead Finder ищет результат в локальном SQLite-кэше за последние 90 дней. Попадание в кэш имеет нулевую стоимость, не увеличивает месячный счётчик API и отображается в истории в колонке **Из кэша**.

Кэшируются только надёжные результаты `site_found` и `likely_no_site`. Неоднозначные ответы, ошибки API и диагностическая проверка подключения не сохраняются. Dry Run кэш не читает и не изменяет.

Рабочие сайты автоматически не перепроверяются. Для них в карточке доступны две кнопки: **Найти актуальный домен** сначала использует кэш, а **Проверить заново за 1 запрос** игнорирует кэш, учитывает запрос в бюджете и обновляет запись только при новом надёжном результате. Ошибка принудительной проверки не удаляет предыдущий кэш.

Новый домен заменяет старый только при одном надёжном совпадении по телефону либо названию и местоположению. Старый URL сохраняется в доказательствах, а новый сайт повторно проходит технический аудит. При ошибке API, нескольких кандидатах или отсутствии подтверждённой замены старый URL не удаляется.

## Импорт своих данных

Поддерживаются CSV и XLSX. Обязательна только колонка `name`.

Допустимые колонки:

```text
name,category,city,address,phone,email,social,website,source,source_url
```

## Необязательный PageSpeed

```powershell
$env:PAGESPEED_API_KEY="ваш_ключ"
py -3.14 -m streamlit run app.py
```

## Локальные данные

- `leads.db` — история лидов, статусы, заметки, согласия, кампании, события, suppression, CRM, финансы и 90-дневный кэш проверки доменов;
- `lead_finder.log` — этапы запуска и ошибки без телефонов, email и заметок.

Для резервной копии достаточно закрыть приложение и скопировать `leads.db`.

## Ограничения

- Полнота компаний и контактов зависит от наполнения OpenStreetMap и результатов Yandex Search API.
- Автоматически оцениваются только проверяемые технические признаки. Субъективная оценка дизайна не выполняется.
- Google Maps, 2ГИС и страницы Яндекс Карт не извлекаются и не сохраняются.
- Публичный Nominatim используется только для границ введённого города; результат кэшируется на 30 дней.
- Статус **Сайт не найден** означает только очередь подтверждения. Утверждение об отсутствии сайта появляется после ручного подтверждения.
- Система не легализует холодную рекламу: доказательство согласия и правовое основание остаются ответственностью отправителя. Автоматическая отправка для `unknown` и `withdrawn` технически заблокирована.
- WhatsApp, автоматическая продажа в Telegram, календарь, банк, бухгалтерия, ЭДО и многопользовательская CRM не входят.
